ReconRaptorAI / Field notes

Stop drowning in recon output. Start hunting the signal.

ReconRaptorAI is the reconnaissance workflow that turns scattered assets, URLs, JavaScript, and scanner output into a review path you can actually use.

ReconRaptorAI•For authorized security testing

Recon is supposed to create opportunity. Too often, it creates a directory full of tools, logs, duplicate URLs, and unanswered questions. ReconRaptorAI gives that work a spine: discover, collect, analyze, validate, triage, review.

What ReconRaptorAI does

ReconRaptorAI is a Bash-based workflow for bug bounty and approved security testing. It chains proven reconnaissance tools into one structured run, then separates raw data from higher-signal reports and supporting evidence.

Discover the surface

Find subdomains, resolve DNS, identify live hosts, collect historical URLs, and crawl live targets.

Read the client side

Download live JavaScript, run Gitleaks, inspect for secrets and client-side indicators, and retain source links.

Validate focused leads

Check exposed files, redirects, CORS, GraphQL, storage, TLS, and takeover signals with evidence-first output.

Choose the next review

Use OpenAI, Ollama, or offline rules to rank leads—then open START_HERE.md for the review path.

Install it

The installer checks for Go and installs the reconnaissance stack: subfinder, dnsx, httpx, katana, nuclei, tlsx, subzy, waybackurls, and gitleaks.

git clone https://github.com/Zuri09/ReconRaptor.git
cd ReconRaptor
chmod +x install.sh reconraptor.sh
./install.sh
./reconraptor.sh -d example.com

For local AI triage, install Ollama alongside the toolchain:

./install.sh --with-ollama
./reconraptor.sh -d example.com --ai --ai-provider ollama

If you are offline or want to leave your existing Nuclei template cache alone, run ./install.sh --skip-nuclei-templates. To select a different local model during installation, use --ollama-model <model>.

Options that matter

OptionWhat it does
-d, --domain <domain>Required target domain to scan.
-w, --webhook <url>Uploads the final results zip to a Discord webhook.
--aiEnables AI-powered triage.
--ai-provider <mode>Choose auto, openai, ollama, or rules.
--ai-model <model>Sets the model name for OpenAI or Ollama.
NUCLEI_TEMPLATE_TAGS=...Overrides the curated Nuclei template tags.
NUCLEI_AUTOMATIC_SCAN=falseDisables the technology-mapped Nuclei scan.

Pick the triage mode that fits the engagement

AI triage is optional. ReconRaptorAI builds a sanitized context file and produces a ranked report. In auto mode it prefers OpenAI when OPENAI_API_KEY is set, then Ollama when available, then offline rules.

# Cloud triage
OPENAI_API_KEY="your_api_key" ./reconraptor.sh -d example.com --ai --ai-provider openai

# Nothing leaves the machine
./reconraptor.sh -d example.com --ai --ai-provider rules

# Choose a local model
./reconraptor.sh -d example.com --ai --ai-provider ollama --ai-model llama3.2:3b

Sanitization removes secret-like query values, raw request and response bodies, downloaded JavaScript bodies, and long text before context is sent to an AI provider. Treat every scan output as sensitive regardless.

The payoff: a review path, not a junk drawer

Every run creates a target directory with a START_HERE.md index. Confirmed or high-confidence results go in reports/findings/; AI summaries in reports/ai/; JavaScript analysis in reports/js/; URL leads in reports/urls/; and downloaded material in evidence/.

That structure does not replace manual verification. It makes the work of verifying more deliberate: start with the strongest lead, trace it to evidence, reproduce it, and only then report it.

Use with permission

ReconRaptorAI is built for assets you own or are explicitly authorized to test. Scanner and AI output are triage leads, not proof—confirm scope and reproduce findings manually.
